# AimiliVPN WebUI 优化方案

## 1. 文档目的

本文针对 AimiliVPN 当前 WebUI 制定可执行的界面与交互优化方案。目标是让管理员能够快速回答三个问题：

1. 当前有哪些可用的 VPNGate 出口？
2. 当前有哪些 sing-box 入站节点，客户端应该使用哪个连接地址？
3. 每个客户端节点实际经过哪个出口，链路是否健康？

本文只规划 WebUI 层的体验、信息架构和接口契约，不改变“客户端 -> sing-box -> 本机回环代理 -> VPNGate 出口”的网络模型。

## 2. 当前问题

### 2.1 信息分散

- 首页同时承担 VPNGate 节点列表、连接控制、系统状态、日志和管理入口，首屏重点不明确。
- sing-box 节点、VPNGate 出口、节点组合虽已拆分管理，但缺少统一的链路视图。
- 服务进程“运行中”和代理链“可用”容易被误读为同一状态。

### 2.2 节点识别成本高

- 相同协议的节点如果没有明确名称，列表和客户端链接难以区分。
- 节点表格缺少稳定的入口端口、绑定出口、最后健康时间等关键信息。
- 客户端链接较长，复制、核对和分享不够顺手。

### 2.3 配置操作风险高

- 保存、应用、重载、失败回滚的结果没有在页面上形成明确的操作反馈。
- 批量修改时缺少“未保存变更”提示和离开页面保护。
- 删除正在被组合引用的节点或出口时，缺少依赖关系提示。

### 2.4 移动端和异常场景不足

- 宽表格在手机上需要横向滚动，核心状态不易扫描。
- 获取节点、连接出口、重载 sing-box 时，等待进度和失败原因不够集中。
- 空数据、失效节点、重试中、权限不足等状态没有统一呈现。

## 3. 设计原则

- **状态优先**：运行状态、链路健康、配置是否已应用必须在页面顶部可见。
- **对象分离**：sing-box 节点、VPNGate 出口、节点组合分别维护；组合页只负责绑定关系。
- **可追溯操作**：每次保存都显示“已保存/已应用/已回滚/等待重试”的明确结果。
- **安全默认**：敏感凭据默认隐藏，复制链接使用显式操作，内部 `7928/7929/...` 端口不作为公网入口展示。
- **渐进披露**：常用字段直接显示，高级协议参数放入折叠区域或编辑抽屉。
- **可恢复**：破坏性操作二次确认，失败操作提供重试和查看日志入口。

## 4. 信息架构

建议将 WebUI 固定为四个一级页面，顶部保留全局状态栏和用户菜单：

| 页面 | 主要职责 | 首要操作 |
|---|---|---|
| 总览 | 查看整体健康、当前出口和待处理事项 | 更新节点、连接/断开、查看故障 |
| sing-box 节点 | 协议入站节点的增删改查和客户端链接 | 新增节点、编辑、启停、复制链接 |
| VPNGate 出口 | 国家/IP 类型筛选、出口生命周期和本地代理端口 | 获取节点、选择节点、连接、停止 |
| 节点组合 | 将 sing-box 节点绑定到 `direct` 或 VPNGate 出口 | 批量绑定、预览链路、应用组合 |

次级功能放入页面内的标签或抽屉：系统日志、网络设置、账号设置、备份与恢复。

## 5. 总览页设计

### 5.1 顶部全局状态栏

显示四个紧凑指标：

- sing-box：运行中/已停止/未安装
- 代理链：健康/降级/已停止
- VPNGate：已连接出口数/目标出口数
- 配置：已应用/有未保存变更/最近应用时间

代理链状态使用统一颜色：健康为绿色、降级为橙色、停止或失败为红色；颜色之外必须同时显示文字，不能只依赖颜色。

### 5.2 当前链路卡片

以列表或简化流程展示每个启用节点：

```text
客户端入口 :4433  ->  sing-box 节点“日本办公”  ->  127.0.0.1:7929  ->  VPNGate 日本  ->  healthy
客户端入口 :8443  ->  sing-box 节点“主机直连”  ->  direct             ->  主机网络    ->  healthy
```

每行提供：节点名称、协议、入口端口、出口名称、出口国家/IP、链路状态、复制链接按钮。

### 5.3 待处理事项

只显示需要管理员操作的事件，例如：

- 出口处于 `retry_wait`，显示下次重试时间。
- sing-box 进程运行但所需本地代理端口未就绪。
- 节点端口冲突或配置校验失败。
- VPNGate 节点列表超过刷新周期。

每条事件提供“查看对象”“重试”“查看日志”操作。

## 6. sing-box 节点页

### 6.1 列表字段

默认字段：

| 字段 | 说明 |
|---|---|
| 名称 | 管理员自定义，必须唯一；重复时保存失败并提示 |
| 协议 | VLESS-REALITY、VLESS、VMess、Trojan、Shadowsocks、SOCKS、HTTP、TUIC、Hysteria2、AnyTLS 等 |
| 入口 | 监听地址和公网入口端口 |
| 出口 | `direct` 或绑定的 VPNGate 出口 |
| 状态 | 启用、禁用、健康、降级、配置错误 |
| 客户端链接 | 复制、查看二维码/文本 |
| 更新时间 | 最近一次配置保存时间 |

敏感字段（私钥、密码、UUID）不在列表中显示。

### 6.2 操作方式

- 新增和编辑使用右侧抽屉，避免离开列表上下文。
- 协议使用下拉选择，切换协议后只显示相关字段。
- 名称、端口、凭据、公共主机名在保存前进行前端校验，后端仍必须再次校验。
- “保存”只保存配置；“保存并应用”保存后执行校验和 reload，并显示结果。
- 启用/禁用使用开关；禁用最后一个节点时允许保存，但服务进入停止状态并明确提示。
- 删除前显示引用该节点的组合数量；被引用时提供“解除组合并删除”或取消。

### 6.3 客户端链接

每个节点的链接区域包含：

- 复制链接按钮，复制成功后显示短暂确认。
- 显示链接按钮，默认脱敏；再次点击才展开。
- 二维码按钮，二维码弹窗中同时显示节点名称、协议、地址和端口。
- 导出按钮，支持单节点文本和批量 JSON/文本导出。

链接生成必须使用节点实际的名称、公共主机名和自定义端口，禁止使用协议默认名称或固定 `4433`。

## 7. VPNGate 出口页

### 7.1 筛选区

筛选条件置于列表顶部并可折叠：

- 国家/地区
- IP 类型：IPv4、IPv6、全部
- 延迟范围
- 速度下限
- 排序：延迟、速度、最近检测时间
- 仅显示可用节点

筛选应支持 URL 查询参数，使刷新和分享后仍能恢复条件。

### 7.2 出口列表字段

显示国家旗标或国家代码、服务器 IP/域名、协议、延迟、速度、OpenVPN 状态、本地代理端口、TUN 设备、健康阶段和最后错误。

运行阶段使用统一顺序：`preparing -> connecting -> tunnel_ready -> proxy_ready -> healthy`；停止和异常显示 `stopping / stopped / failed / retry_wait`。

### 7.3 操作

- “更新节点”显示拉取、解析、测速、排序四个阶段。
- “选择”只改变候选配置；“连接”才启动出口。
- 连接中按钮变为可取消的进度状态，避免重复启动。
- 失败行提供“重试”“查看日志”“更换节点”。
- 删除或停用出口前显示受影响的 sing-box 节点组合。

## 8. 节点组合页

### 8.1 核心布局

采用“左侧 sing-box 节点列表 + 右侧出口选择”的密集表格：

| sing-box 节点 | 协议/入口 | 出口选择 | 预期链路 | 实际状态 |
|---|---|---|---|---|
| 日本办公 | VLESS :4433 | VPNGate 日本 | `127.0.0.1:7929` | healthy |
| 备用直连 | Trojan :8443 | direct | 主机网络 | healthy |

出口下拉选项必须同时显示名称、国家、本地端口和阶段，不能只显示一个 ID。

### 8.2 应用流程

1. 修改绑定后标记“有未应用变更”。
2. 点击“预览变更”显示新增、移除和受影响节点。
3. 点击“应用组合”执行配置校验、原子写入、reload 和健康检查。
4. 成功显示每个节点的实际链路；失败显示回滚结果和日志入口。

组合页不得隐藏 sing-box 节点的启用状态；禁用节点应置灰并说明原因。

## 9. 统一状态与反馈规范

### 9.1 状态模型

前端统一消费以下字段：

```json
{
  "chain_state": "healthy|degraded|stopped",
  "chain_ready": true,
  "chain_error": "",
  "required_exits": ["japan"],
  "missing_exits": [],
  "unhealthy_exits": [],
  "phase": "proxy_ready",
  "last_transition_at": 1710000000,
  "retry_at": null
}
```

### 9.2 通知策略

- 保存成功：页面内绿色提示，不打断当前编辑。
- 应用中：顶部显示全局进度，按钮锁定，最长等待时间明确。
- 应用失败：红色提示包含原因、是否已回滚、重试按钮。
- 后台状态变化：使用轻量通知，不弹出遮挡式模态框。
- 连续失败：提升到总览页“待处理事项”，而不是只留在日志中。

## 10. API 与前端数据层

建议将页面请求统一封装为 `apiFetch()`：

- 自动处理 JSON、401、403、429、网络超时。
- 对保存类请求附带请求 ID，便于日志关联。
- 对状态接口使用 5-10 秒轮询，页面不可见时暂停；连接/应用期间临时提高频率。
- 保留最近一次成功数据，网络短暂失败时显示“数据更新时间”，不要清空列表。

建议补充或统一以下响应字段：

- `/api/singbox/status`：服务状态、链路状态、出口健康明细、节点健康明细。
- `/api/singbox/combinations`：节点、出口、当前映射、配置版本和未应用标记。
- `/api/vpn-exits`：筛选结果、节点总数、更新时间、出口运行阶段。
- 所有保存接口：`config_version`、`applied`、`rolled_back`、`request_id`。

## 11. 响应式与可访问性

- 桌面端使用两栏布局，最小宽度 1024px；移动端改为单列和抽屉编辑。
- 表格在移动端转换为对象卡片，优先显示名称、状态、入口、出口和主要操作。
- 所有图标按钮提供 `title` 和可访问名称；复制、编辑、删除、查看链接使用熟悉图标。
- 键盘可完成新增、保存、关闭抽屉和切换节点；焦点不能丢失。
- 文本、状态和按钮不能依赖颜色；保证足够对比度和触控尺寸。

## 12. 安全与隐私

- 客户端链接、密码、私钥默认隐藏，复制动作需要明确点击。
- 页面不展示管理密码明文，也不把密码写入 URL、日志或错误消息。
- WebUI 端口和 sing-box 公网端口单独展示；`7928/7929/...` 明确标记为“仅本机回环”。
- 删除、停止出口、批量应用使用二次确认，并展示影响范围。
- 前端错误提示只展示可操作信息，详细命令输出进入受保护日志接口。

## 13. 实施阶段

### 阶段 A：信息架构和基础组件

- 建立顶部状态栏、页面导航、统一提示、抽屉、确认框、状态徽标组件。
- 抽取 `apiFetch()`、轮询和错误处理逻辑。
- 统一颜色、间距、按钮、表格和移动端断点。

### 阶段 B：sing-box 节点页

- 完成列表字段、搜索、协议动态表单、唯一名称校验。
- 完成复制链接、二维码、链接脱敏和批量导出。
- 接入保存/应用事务状态。

### 阶段 C：VPNGate 出口页

- 完成国家/IP 类型筛选、排序、测速进度和生命周期阶段。
- 增加依赖关系提示和失败重试。

### 阶段 D：组合页和总览页

- 完成组合预览、批量应用、回滚反馈。
- 完成链路流程视图和待处理事项。

### 阶段 E：验证与发布

- 桌面端、窄屏和移动端截图验收。
- 覆盖空数据、权限失败、429、服务停止、出口重试、配置回滚等异常场景。
- 使用真实 sing-box 二进制验证生成配置和客户端链接。

## 14. 验收标准

- 管理员在总览页 5 秒内能判断 sing-box、VPNGate 和代理链是否健康。
- 两个相同协议节点可以通过名称、入口端口和复制链接准确区分。
- 组合页能清楚展示 `direct`、本地代理端口和 VPNGate 国家出口。
- 进程运行但出口未达到 `proxy_ready/healthy` 时，页面必须显示“降级”，不能显示“链路已就绪”。
- 保存或应用失败后，页面能明确显示是否回滚，且刷新后配置与运行态一致。
- 移动端无需横向滚动即可完成查看、启停、复制链接和组合绑定。
- 敏感凭据默认不可见，内部回环端口不会被误认为公网端口。
